# X3 玄师统一角色舞台设计规格

日期：2026-09-22  
状态：设计已确认，待实现计划  
选择：A——四角色完整文化场景

## 目标

解决当前玄师舞台“有的角色有背景、有的角色没有”和信息层级混乱的问题。四位角色都使用完整文化场景，但共享同一套舞台容器、人物位置、标题区域和底部内容抽屉。文化差异通过场景、色温、道具和光影表达，不再通过是否显示背景表达。

## 统一舞台结构

从后到前固定为五层：

1. `ScenePlate`：铺满舞台的角色场景图或可组合场景。
2. `SceneScrim`：统一的上下渐变遮罩，保证文字对比度。
3. `CharacterLayer`：人物主体固定在安全区域内，不能遮挡标题、分数或底部导航。
4. `StageHeader`：角色姓名、文化灵感、当前专长和关闭按钮。
5. `CompanionDrawer`：对话、专长、游戏三类入口；长回复默认折叠。

`MysticImmersiveStage` 负责容器和安全区，`MysticScenePlate` 负责场景，`MysticCharacterFigure` 负责人物，`CompanionDrawer` 负责内容。角色切换只替换 profile、scene 和 palette，不改变容器结构。

## 四套完整场景

| 角色 | sceneId | 场景内容 | 视觉约束 |
|---|---|---|---|
| 沈砚舟 | `jiangnan_triptych` | 水榭、月桥、灯影、远山 | 冷青灰底，暖灯作为焦点 |
| 墨衡 | `ink_elder` | 水墨案头、宣纸、砚台、山水屏风 | 低饱和墨灰，保留老人形象的清晰轮廓 |
| 伊芙琳·诺瓦 | `academy_triptych` | 学院观测室、星图、档案桌 | 深蓝紫底，星点只作静态纹理 |
| 纳迪尔·拉希德 | `silkroad_triptych` | 丝路驿站、沙丘、铜盘、灯火 | 暖赭石底，避免高亮遮盖面部 |

场景资源可以是完整背景图，也可以由背景图和少量 Canvas 纹理组合，但最终必须填满舞台。资源读取失败时统一回退到低对比水墨渐变和角色色板，禁止出现纯黑空洞或与其他角色不同的透明例外。

## 内容密度与交互

- 舞台顶部只显示姓名、文化灵感、专长和关闭按钮。
- 对话、查看专长、进入当前角色游戏集中在底部抽屉。
- 对话气泡靠近人物下方显示，超过预览长度默认折叠。
- 评分、依据和每日行动不直接覆盖人物；需要查看时在抽屉内展开。
- 角色横向 Pager、浮球召回、返回键和关闭舞台保持现有行为。
- 背景和人物不做持续位移；reduced-motion 下仅保留静态场景和轻微透明度变化。

## 无障碍与安全区

- 使用 `statusBarsPadding`、`navigationBarsPadding`、`imePadding` 和滚动容器，避免遮挡系统手势区、底部导航、分数卡和输入框。
- 场景装饰标记为非语义内容；人物和角色切换目标提供姓名、文化灵感、专长和当前状态的 content description。
- 关闭按钮最小触控尺寸 48dp，键盘和 TalkBack 可达。
- 窄屏和横屏下人物缩放优先于裁剪，文字优先于装饰。

## 数据与边界

- 场景只消费 `MysticCharacterProfile.sceneId`、`visualStyleId` 和 `gameTheme`，不改变命理、占星或游戏算法。
- 不新增占卜体系、不伪造文化权威、不把场景文案写入长期记忆。
- 背景切换不会改变对话线程、盘面事实、软标签或确定性 seed。

## 验收与测试

1. JVM：四个 sceneId、统一回退、角色推荐和对话确定性测试。
2. Compose/androidTest：四角色均存在场景语义、标题、关闭按钮和动态游戏入口；窄屏不溢出。
3. 构建门禁：`testDebugUnitTest`、`lintDebug`、`assembleDebug`、`assembleDebugAndroidTest`。
4. 真机：四角色截图、滑动切换、返回/关闭、旋转、TalkBack、reduced-motion 和 Logcat，单独记录为设备验收，不以编译结果替代。

## 明确不做

- 本规格不重绘四位人物本身，只统一人物与场景的层级和比例。
- 本规格不接入联网图片、天气、地图或在线模型。
- 本规格不删除现有角色游戏和对话持久化能力。
