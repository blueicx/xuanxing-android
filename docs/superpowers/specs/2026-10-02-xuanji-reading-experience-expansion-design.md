# X3 运势阅读与玄师陪伴扩充规格

## 背景与目标

在现有 v14 运势卡片、详情页、四角色玄师、行动建议和本命排盘基础上，补齐从阅读、深入解释、收藏回顾到角色对话的连续体验。此次以已确认的扩充原型为布局依据，不重做已确认的视觉语言，不删减旧版内容，不改变现有占卜算法或真实体系声明。

目标是：

- 每个可深入阅读的板块都能进入完整详情，并可从详情直接带着当前结果询问玄师。
- 用户明确收藏的运势、行动、玄师与游戏摘要可本地回顾、筛选、撤回或删除。
- 周、月、年视图利用既有周期结果提供清晰的趋势解释；今日行动仍只出现在今日。
- “一生命盘”继续作为独立主入口，集中呈现终身结构；今日详情不跳转到本命盘。
- 今日行动更贴合明确饮食/活动偏好，已采纳、不合适、换一个等主动反馈能影响后续候选排序且可撤销。
- 角色线程和游戏存档上下文相互衔接，但不混淆生成回复、长期记忆和游戏状态。

## 现有能力与不变基线

- 「今日」内已有综合 / 东方 / 西方切换，日 / 周 / 月 / 年周期切换；东方使用农历日期格式。
- 综合、东方、西方页已有独立周期结果；综合行动卡只在 `day` 周期挂载。
- `FortuneDetailPage` 已提供全屏详情容器，要求完整展示传入内容；`FortuneDetailPageTest` 锁定详情内容语义。
- 今日行动已有具体菜名、食材、替代品、预算/准备时间、依据和本地饮食偏好存储；`DailyActionPlanner` 已以五行、星座、盘面、季节/城市确定性排序。
- 「我的」已保留出生资料、当前档案、人生画像、饮食偏好、玄师设置、关于与隐私等既定顺序。不得挪走或删除这些入口。
- 「排盘」已经是独立的「一生命盘」入口，东方本命和西方本命复用已有计算与展示。
- 四角色、按角色隔离的对话线程、游戏存档、对话动作路由、数据导出/清除均已有基础实现；本轮沿用这些边界，不另造平行状态系统。
- 卡片继续使用 v14 表面 token。已有分类名称、内容、评分、依据、行动语义和详情文本均保留；此规格新增导航、承接与补充信息，不以精简为由删旧内容。

## 功能规格

### 1. 运势详情与玄师直达

- 综合、东方、西方及今日行动的每一个可点击详情，都沿用现有全屏详情呈现完整内容。
- 详情底部增加主要动作“问玄师”（已选定 A 方案）；不增加首页重复行动卡或多余的“换一个/已采纳/不合适/为什么”快捷按钮组。
- 动作以结构化上下文打开当前已选角色线程：包括当前模式、周期/日期、板块标题、实际显示的计算结果、已有依据/来源状态。不得只传一段泛化问题，也不得重新随机生成或改变刚才看到的结果。
- 如果缺少必要计算数据，清楚说明缺少项并允许进入普通对话；不补造盘面事实。
- 关闭对话后回到原详情，保留详情滚动位置、展开状态和父页面滚动位置。详情对话不得把用户送去「排盘」。
- 旧请求 token 规则继续生效；切换角色、主题或会话后，旧回复不得覆盖当前内容。

### 2. 记录与收藏

- 「记录」保留「历史上的今天」和「同月同日生」全部现有内容，新增「我的收藏」分区，不替换现有记录分类。
- 仅当用户主动点选收藏时保存。支持运势详情、行动卡、玄师单条回复和已完成游戏摘要；收藏列表支持类型筛选、关键词搜索、打开原快照、逐条取消收藏及明确确认后的批量清除。
- 收藏回看的是保存时快照，不自动重算、不冒充当前结果。快照记录标题、类别、日期/周期、运势模式、角色/游戏 ID（若适用）、结果正文/分段、来源与算法版本；不默认保存出生原文、未收藏的会话、输入框草稿或被动行为。
- 数据只保存在本机，按 profile hash 隔离；增加版本化编码、损坏降级与迁移测试。导出预览可包含收藏摘要，删除/清除应同步删除本地快照；更换档案不得串读。
- 收藏入口和状态需有无障碍标签；取消收藏可以撤销当前操作，清除整个集合前必须明确确认。

### 3. 周 / 月 / 年趋势

- 保留顶部已有的周期切换和三种运势模式切换位置、选中状态及各模式的日期语义。
- 周、月、年页显示对应周期分数、总评、主要维度变化、已计算的依据/缺失输入和更完整的周期解说；继续沿用现有分类与术语。
- 若生成曲线或阶段比较，只能由现有确定性算法针对明确日期/周期计算；标签注明它是离线算法参考，不称为历史观测、保证预测或实时事实。没有对应数据时显示明确空态，不填示意分数冒充结果。
- 今日行动、食物、活动、出游卡仅在今日周期展示；周、月、年页不出现这些卡片，也不在其他区域重复今日行动卡。
- 东方当前模式继续显示与所选日期一致的农历日期；综合、西方使用公历日期。

### 4. 一生命盘与人生画像

- 「排盘」仍是独立的一生命盘，不被今日详情替代。页内分为「人生概览 / 东方本命 / 西方本命」三个清晰入口；概览可呈现已有的职业倾向、色彩灵感、环境与地区匹配摘要，并可深入现有 LifeProfile 依据。
- 东方和西方子页继续复用已有 `chartOnly` 本命盘结果；扩充阅读层级和解释入口，不改计算口径、不删原有盘面内容。
- 出生资料编辑入口仍指向现有档案编辑处；缺少出生时刻、地点或其他输入时标清影响，不伪装完整。
- 每个解释区分计算结果、文化参考、未启用能力，并展示现有可取得的来源、版本、seed、置信度和缺失输入。
- 不推断人格，不给医疗、投资、迁居安全、移民或职业成败结论。人生画像保持为匹配参考，并解释匹配与未覆盖因素。
- 「我的」仍保留其当前用户已确认的内容和顺序；本命概览可链接到相关设置/画像，不通过删除「我的」内容制造唯一入口。

### 5. 行动建议偏好与反馈闭环

- 继续使用现有 `FoodPreferenceStore`、`FoodPreferenceEditor`、`ActionConstraints`、`DailyActionPlanner` 和 `ActionFeedbackDataStore`；本轮不增加联网菜谱/天气/地图服务。
- 饮食硬限制（过敏原、排除食材、素食/清真等）先过滤，再进行五行 + 星座 + 盘面 + 季节/城市的固定权重排序。过滤结果为空时明确提示调整偏好，不退回不符合限制的菜品。
- 已采纳、不合适、换一个是用户显式选择。仅在同 profile、同类型的行动候选排序中使用有限、可解释的权重调整；不得转成用户性格或健康标签。更改/撤销及清除应可见，最近一次“换一个”可撤销。
- 详情继续显示具体菜名、食材、替代品、费用/准备时间、筛选限制和计算依据；健康与营养内容仅作生活方式灵感，不作医疗建议。

### 6. 四角色线程与游戏承接

- 保留沈砚舟、墨衡、伊芙琳·诺瓦、纳迪尔·拉希德四个既定身份、场景差异、独立线程和专长映射。
- 从运势详情进入对话时，角色读取当前所选角色而非另行自动挑选；共享当前盘面与用户主动记忆，消息只进入对应角色线程。
- 通过详情或对话进入游戏时，打开现有角色专属游戏并恢复本地存档；从游戏返回时保留线程和导航位置。对话引用进度必须来自真实存档；无存档则诚实说明。
- 棋类规则、诗句库、星图逻辑、丝路路线使用现有引擎与授权明确内容；此轮不新增假局面或把游戏结果包装成占卜事实。

## 数据与状态边界

- 收藏、饮食偏好、行动反馈、角色线程、盘面结果和游戏存档分别使用既有或新设的版本化本地 store，不共用一个无类型 JSON 状态袋。
- 收藏结果与角色长期记忆分离：收藏只表示用户要保留的可见结果，不自动写成“我记得你”的软标签。
- 会话离开/返回应保留当前视图；进程重建后恢复应恢复已持久化数据，未提交输入草稿可按现有行为清空。
- 所有旧版本或损坏数据需有显式、可测的安全降级；不因迁移失败静默覆盖其他档案数据。

## 非目标与安全边界

- 不接入在线模型、地图、GPS、天气或其他外部服务；不新增占卜体系或宣称新的传统权威性。
- 不自动推断人格、健康、投资能力、现实旅行安全、移民或居住适配结论。
- 不删除、更名或重排既有运势分类，不压缩旧版详情内容；不重复显示首页已有的行动卡和快捷按钮。
- 不安装手机、不改动手机设置、不清用户数据。实体设备视觉、TalkBack、Logcat 验收仍等待用户通知；源码/模拟器测试不能代替实机结论。
- 不在本轮无边界拆分大文件；只在触及的 UI、store、路由和纯 Kotlin 模型处建立可测试的职责边界。

## 验收标准

- 详情到对话：至少覆盖综合/东方/西方维度、今日行动；断言携带当前真实结果和依据、落入正确角色线程，关闭后恢复原详情和滚动位置。
- 收藏：保存、枚举/筛选、搜索、取消、撤销、清除、导出摘要、profile 隔离、版本迁移、损坏数据降级、进程重启恢复均有纯 Kotlin 或 repository 测试。
- 周期：日/周/月/年和综合/东方/西方状态切换正确；农历/公历标签正确；行动卡只在 day 出现；无趋势源时无假数据。
- 本命盘：概览/东方/西方入口互相切换；人生画像取现有 planner 输出；每日详情不进入一生命盘；缺失输入、版本和来源状态显示诚实。
- 行动反馈：硬偏好先过滤；显式反馈可解释地影响候选次序，可撤回/清除，且不生成自动人格/健康字段。
- 角色与游戏：四个角色消息隔离，详情上下文和游戏实际存档相关；不存在存档时诚实回退，旧 token 结果丢弃。
- 工程门禁：现有 Node 契约、`:app:testDebugUnitTest`、`:app:lintDebug`、`:app:assembleDebug`、`:app:assembleDebugAndroidTest` 通过；新增 Compose 交互测试真实执行发送、保存、切换和返回，不只断言节点存在。
- 更新 README、`SYSTEMS_OVERVIEW.md`、`docs/TECHNICAL_DEBT.md` 和新增 dated handoff；旧交接作为历史记录不覆盖。

## 实施拆分

实现计划按依赖分为：

1. 详情上下文路由与页面恢复（先验证 A 方案核心链路）。
2. 收藏快照 store、记录页和隐私导出/清除。
3. 周/月/年趋势呈现及一生命盘概览；只消费既有算法输出。
4. 行动反馈对候选排序的有限应用和撤销入口。
5. 四角色游戏进度对话引用、文档同步与跨模块回归。

每个波次先添加失败测试，再实现。波次间不得改变稳定算法的权重或用户已确认的分类/内容；若必须修改算法，另列版本和迁移测试。
