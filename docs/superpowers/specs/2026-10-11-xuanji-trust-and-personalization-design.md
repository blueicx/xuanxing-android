# X3 可信与个性化收口设计

## 目标

在不新增占卜体系、不联网、不推断用户人格的前提下，补足资料完整度说明、显式行动偏好、安全备份和近期回顾，并以低风险方式继续拆分对话大文件。

## 设计

### 资料完整度与依据

使用独立的纯 Kotlin 评估器展示出生日期、出生时间、出生地域、经纬度和性别是否已录入，以及各字段在当前项目中的用途。它只描述数据状态，不合成置信度、不改变任何运势算法，也不把缺项补成默认用户事实。玄师“依据”仍通过现有 `MysticEvidenceTrace` 展示来源；资料完整度卡片提供进入个人档案的入口。

### 明确偏好驱动行动

饮食过滤沿用现有 `FoodPreference`。新增按档案隔离的活动偏好存储，仅保存低/中/高精力、只选室内和最长活动时长；`ActionRepository` 将其传给现有 `DailyActionPlanner`，没有偏好时保持当前默认排序。偏好仅来自用户保存的控件，不从浏览、聊天或反馈推断。

### 加密备份

保留当前选择性备份 JSON 格式及旧文件导入能力，新增单独的加密容器：PBKDF2-HMAC-SHA256 派生 AES-256 密钥，AES-GCM 提供机密性和认证，随机盐与 nonce 随文件保存；密码只存在于当前 UI 状态，不写入 DataStore、日志或文件。错误密码、损坏数据、超大文件和跨档案文件均在预览阶段拒绝，不写本地状态。明文导出必须有显式选择和“文件未加密”提示。

### 周/月回顾

近期记录继续只来源于用户收藏和明确行动反馈。新增按 ISO 周与自然月的汇总，统计收藏、采纳、不合适、换掉，不用采纳率推断个人偏好，也不读取聊天、页面浏览或游戏被动状态。没有数据时显示诚实空态。

### 定向拆分

把 `MysticGuideGenerator.kt` 顶部纯数据模型移到 `MysticGuideModels.kt`；把 `MysticGuideCard.kt` 尾部纯展示小组件移到 `MysticStageDecorations.kt`。仅移动声明，不改变生成逻辑、文案、种子、调用点或界面布局。

## 验收

- JVM 测试覆盖资料字段状态、行动偏好持久化/档案隔离和过滤、备份加密往返/错误密码/损坏降级、周/月汇总和空态。
- Compose 测试覆盖偏好保存入口、资料完整度可读文案、加密备份密码交互和回顾周期切换。
- 现有 Node 契约及 `testDebugUnitTest`、`lintDebug`、`assembleDebug`、`assembleDebugAndroidTest` 通过。
- 不提交、不推送、不连接或安装手机；不以自动化通过代替人工视觉/无障碍验收。
